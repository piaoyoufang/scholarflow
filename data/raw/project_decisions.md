# ScholarFlow 项目决策记录

## 为什么第十步先用 [MCP] 前缀做显式路由

ScholarFlow 在第十步先使用 [MCP] 前缀做显式路由，是为了保证 MCP 接入过程稳定、可调试、可回滚。

显式路由的好处是：

1. 可以确认普通 Python 函数本身能运行；
2. 可以确认 MCP Server 能暴露工具；
3. 可以确认 MCP Client 能发现并调用工具；
4. 可以确认 LangGraph 中的 mcp_search 节点真的拿到了 mcp_results；
5. 不会破坏原来 RAG 的 20 题评估基线。

当这几层都稳定后，才进入第十一步：让 Qwen 自动判断是否需要调用 MCP。

## 为什么不要一开始就做多 Agent

ScholarFlow 的合理升级顺序是：先做稳定 RAG，再接只读 MCP，再做自动工具路由，最后再考虑多 Agent。

如果一开始就做多 Agent，失败原因会混在一起：可能是资料问题、检索问题、Prompt 问题、工具问题，也可能是 Agent 协作问题。初学阶段应该先保证每一层都能单独验收。

## 当前 MCP 工具的边界

当前 MCP 工具 search_local_knowledge 是只读工具，只负责查询本地补充资料，不修改文件、不发送消息、不提交数据。

只读工具适合先接入，因为风险低、容易测试、适合教学。

如果以后加入写操作工具，例如修改文件、发送邮件、提交表单，LangGraph 中应该加入人工确认节点。
