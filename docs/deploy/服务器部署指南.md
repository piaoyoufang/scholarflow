# scholarflow 服务器部署指南

> 项目：高校课程 AI 学习助手平台（FastAPI 后端 + Vue3 前端 + MySQL/Redis/Qdrant）
> 版本：VERSION = 1.1.0
> 适用：新购云服务器首次部署

---

## 一、部署总览

本项目是「前后端分离」架构，生产环境由 4 部分组成：

```
                     用户浏览器
                        │
                        ▼
                 ┌──────────────┐
                 │  Nginx :80   │  ← 前端静态站点 + /api 反向代理
                 └──────┬───────┘
              /api/*    │   静态资源(dist)
                        ▼
              ┌──────────────────┐
              │ FastAPI api:8000 │  ← 容器
              └───┬────┬─────┬───┘
                  │    │     │
        ┌─────────┘    │     └─────────┐
        ▼              ▼               ▼
   ┌─────────┐   ┌──────────┐   ┌──────────────┐
   │ MySQL   │   │  Redis   │   │ Qdrant/Chroma│
   │  :3306  │   │  :6379   │   │  (数据卷)    │
   └─────────┘   └──────────┘   └──────────────┘
```

- **后端 API**：容器内 `8000`，对外由 Nginx 以 `/api` 前缀暴露。
- **MySQL**：容器内 `3306`，建议只走容器内网，不对外。
- **Redis**：容器内 `6379`，同上。
- **向量库**：Qdrant（本地路径 `/app/data/qdrant_local`）+ Chroma 共存，挂在数据卷上。
- **前端**：Vue3 构建产物 `dist/`，交给 Nginx 托管。
- **Streamlit 原型（`ui.py`，端口 8501）**：仅在需要对照演示时才启用，正式部署可不暴露。

> 仓库里已自带 `Dockerfile` 与 `docker-compose.yml`，因此推荐 **方案 A：Docker Compose 一键部署**。

## 二、部署前准备

### 2.1 服务器要求

| 项目 | 建议 |
|------|------|
| CPU / 内存 | 2 核 4G 起步（向量检索 + LLM 调用，1 核 2G 会吃力） |
| 磁盘 | ≥ 40G（模型无关，但向量库/上传文件/镜像会增长） |
| 系统 | Ubuntu 22.04 / 24.04（推荐）、CentOS 7+、Debian 12 |
| 网络 | 国内服务器访问 `dashscope.aliyuncs.com` 正常即可 |

### 2.2 需要在控制台做的两件事

1. **放行安全组端口**：至少放行 `80`（HTTP）、`443`（HTTPS）。`8000/3306/6379` **不要**直接对外开放，走 Nginx 代理即可。
2. **准备好百炼 Key**：本项目依赖阿里云百炼（DashScope）的大模型与 Embedding/Rerank，需要有效的 `DASHSCOPE_API_KEY`。

### 2.3 登录服务器

```bash
ssh root@<你的服务器公网IP>
```

> Windows 可使用 PowerShell 自带 ssh，或用 Xshell / MobaXterm / FinalShell。

## 三、方案 A：Docker Compose 部署（推荐）

### 步骤 1：安装 Docker 与 Docker Compose

```bash
# 一键安装脚本（国内源）
curl -fsSL https://get.docker.com | bash -s docker --mirror Aliyun

# 启动并设为开机自启
systemctl enable --now docker

# 验证
docker --version
docker compose version
```

> 若 `docker compose` 不存在，装 `docker-compose-plugin`：
> `apt-get install -y docker-compose-plugin`（Ubuntu）或 `yum install -y docker-compose-plugin`（CentOS）。

### 步骤 2：配置 Docker 镜像加速（重要）

服务器拉取镜像可能很慢或被限流。仓库里的 `Dockerfile` / `docker-compose.yml` 默认使用 `docker.1ms.run` 加速地址，若该地址在你的服务器不可用，需配置全局镜像加速：

```bash
sudo tee /etc/docker/daemon.json <<'EOF'
{
  "registry-mirrors": ["https://docker.1ms.run"],
  "log-driver": "json-file",
  "log-opts": { "max-size": "50m", "max-file": "3" }
}
EOF

sudo systemctl daemon-reload
sudo systemctl restart docker
```

> 若该镜像站失效，可替换为其他可用镜像站，或让服务器直连 Docker Hub（在 `docker-compose.yml` 中把 `PYTHON_BASE_IMAGE` 改为 `python:3.11-slim`、`mysql` 改为 `mysql:8.0`、`redis` 改为 `redis:7-alpine`）。

### 步骤 3：拉取项目代码

方式一（Git）：

```bash
mkdir -p /opt && cd /opt
git clone <你的仓库地址> scholarflow
cd scholarflow
```

方式二（本地上传）：用 `scp` 把本地 `D:\python\ai-project\scholarflow`（排除 `node_modules`、`data`、`logs`、`__pycache__`）上传到服务器 `/opt/scholarflow`。

```bash
# 本地 Windows PowerShell 示例
scp -r D:\python\ai-project\scholarflow root@<IP>:/opt/scholarflow
```

### 步骤 4：准备生产环境变量

```bash
cd /opt/scholarflow
cp .env.production.example .env.production
vi .env.production
```

**必须修改的关键项**：

| 变量 | 说明 | 必改 |
|------|------|------|
| `DASHSCOPE_API_KEY` | 你的百炼 Key，替换示例占位值 | ✅ |
| `DATABASE_URL` | 容器网络内应指向 `mysql:3306`（示例已是） | 确认 |
| `REDIS_URL` | 容器网络内应指向 `redis:6379/0`（示例已是） | 确认 |
| `API_BASE_URL` | 容器内为 `http://api:8000`（示例已是） | 确认 |
| `QDRANT_PATH` | `/app/data/qdrant_local`（示例已是） | 确认 |

> ⚠️ 仓库里已存在的 `.env.production` 内含一个**真实 API Key**，请务必：① 换成你自己的 Key；② 尽快在百炼控制台**废弃旧 Key**；③ 确认该文件未被提交到 Git（`.gitignore` 已忽略 `.env.production`）。

### 步骤 5：调整对外端口（可选）

`docker-compose.yml` 默认把 MySQL 映射到宿主机 `3307`、Redis 到 `6379`。**生产环境建议去掉这两个端口映射**，只保留容器内网互通，避免数据库直接暴露公网。编辑 `docker-compose.yml`，删除 `mysql` 和 `redis` 服务下的 `ports:` 段即可。

### 步骤 6：构建并启动

```bash
cd /opt/scholarflow
docker compose up -d --build
```

查看状态与日志：

```bash
docker compose ps
docker compose logs -f api
```

期望：`scholarflow-mysql`、`scholarflow-redis` 健康（healthy），`api` 容器正常运行。

### 步骤 7：初始化 MySQL 表结构

首次启动 MySQL 是空库，需要初始化表结构（把 SQLite 存量数据迁移到 MySQL 也在此步）：

```bash
# 初始化 MySQL schema
docker compose exec api python scripts/init_mysql_schema.py

# 如需把本地 SQLite 数据迁移进 MySQL（可选）
# docker compose exec api python scripts/migrate_sqlite_to_mysql.py
```

### 步骤 8：验证后端

```bash
# 容器内健康检查
curl http://127.0.0.1:8000/health

# 就绪检查
curl http://127.0.0.1:8000/health/ready
```

返回 200/正常 JSON 即说明后端与 MySQL、Redis 已联通。

## 四、前端构建 + Nginx 托管

后端 API 跑起来后，再部署 Vue3 前端。

### 步骤 1：构建前端

服务器上需要 Node.js 18+：

```bash
# 安装 Node（如未安装；或用 nvm）
curl -fsSL https://deb.nodesource.com/setup_20.x | bash -
apt-get install -y nodejs

cd /opt/scholarflow/vue-frontend
npm install
npm run build
```

构建产物在 `vue-frontend/dist/`。

> 前端 API 基址由 `vue-frontend/.env.development` 的 `VITE_API_BASE_URL=/api` 决定（生产也走 `/api`），由 Nginx 反向代理到后端，因此**无需**在前端里写死服务器 IP。

### 步骤 2：安装 Nginx

```bash
apt-get install -y nginx
systemctl enable --now nginx
```

### 步骤 3：配置站点

新建 `/etc/nginx/conf.d/scholarflow.conf`：

```nginx
server {
    listen 80;
    server_name <你的域名或公网IP>;

    # 前端静态文件（改为 dist 实际路径）
    root /opt/scholarflow/vue-frontend/dist;
    index index.html;

    # 上传大文件（课程资料 PDF 等）
    client_max_body_size 50m;

    # SPA 前端路由回退
    location / {
        try_files $uri $uri/ /index.html;
    }

    # 反向代理后端 API：/api/xxx -> 后端 /xxx
    location /api/ {
        proxy_pass http://127.0.0.1:8000/;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # AI 问答/出题耗时较长，放宽超时
        proxy_read_timeout 300s;
        proxy_send_timeout 300s;
        proxy_connect_timeout 60s;
    }
}
```

> 注意 `proxy_pass http://127.0.0.1:8000/;` **末尾的斜杠**：它会把 `/api/auth/login` 转成 `/auth/login`，与后端路由一致。
> 若 Nginx 直接装在宿主机（非容器），用 `127.0.0.1:8000`；若 Nginx 也在 compose 网络内，用 `http://api:8000/`。

校验并重载：

```bash
nginx -t
systemctl reload nginx
```

### 步骤 4（可选）：配置 HTTPS

```bash
apt-get install -y certbot python3-certbot-nginx
certbot --nginx -d <你的域名>
```

### 步骤 5：验证

浏览器访问 `http://<服务器IP>`，应看到登录页；注册/登录后验证课程、上传、问答流程。

## 五、方案 B：宝塔面板部署（备选，适合不熟命令行）

1. 面板安装 **Nginx + MySQL 8.0 + Redis + Python 项目管理器**。
2. 建站点，域名解析到服务器，根目录指向 `vue-frontend/dist`。
3. 站点设置里加反向代理：目标 `http://127.0.0.1:8000`，代理目录 `/api`。
4. 用「Python 项目管理器」添加后端项目：
   - 启动命令：`uvicorn app.api:app --host 0.0.0.0 --port 8000 --workers 1`
   - 环境变量：按 `.env.production` 填，但 `DATABASE_URL` 用 `127.0.0.1:3306`、`REDIS_URL` 用 `127.0.0.1:6379`。
5. 在宝塔 MySQL 里建库 `scholarflow`（utf8mb4），执行 `scripts/init_mysql_schema.py` 初始化。
6. 放行对应端口（一般只需 80/443，后端 8000 只在本机监听）。

## 六、常见问题排查

| 现象 | 排查方向 |
|------|----------|
| `docker compose up` 拉镜像超时 | 配置镜像加速（见步骤 2），或改 `docker-compose.yml` 基础镜像 |
| api 容器反复重启 | `docker compose logs api` 看是否 `DASHSCOPE_API_KEY` 缺失或数据库连不上 |
| `/health/ready` 不通过 | MySQL/Redis 未 healthy；等健康检查通过，或查 `docker compose ps` |
| 前端页面能开但接口 404 | Nginx `/api` 代理路径或末尾斜杠写错；确认 `proxy_pass ...:8000/` 有斜杠 |
| 接口 502 | 后端未起或端口不对；`curl 127.0.0.1:8000/health` 自测 |
| 问答超时 | Nginx `proxy_read_timeout` 调大（本配置已 300s）；模型并发受限 |
| 上传大文件失败 | Nginx `client_max_body_size` 调大 |
| 问答/出题报大模型错误 | 检查 `DASHSCOPE_API_KEY` 是否有效、额度是否充足、服务器能否访问 dashscope |
| 数据丢失 | 确认 `data/`、`logs/` 已通过 volume 挂载到宿主机并做好备份 |

## 七、上线安全检查清单

- [ ] `.env.production` 使用的是**你自己的**百炼 Key，且旧 Key 已在控制台废弃
- [ ] `.env.production` 未被提交进 Git（`.gitignore` 已忽略）
- [ ] MySQL / Redis **未**直接映射到公网端口
- [ ] 安全组只开放 80 / 443（必要时加 SSH 端口）
- [ ] MySQL 默认口令 `scholarflow_pwd` 已改为强口令（同步改 `docker-compose.yml` 与 `.env.production`）
- [ ] 配置了 HTTPS
- [ ] `data/`、`logs/`、数据库已纳入备份计划（可参考 `scripts/backup_data.py`）
- [ ] `docker compose` 服务 `restart: unless-stopped` 已生效（开机自启）

## 八、日常运维命令

```bash
cd /opt/scholarflow

docker compose ps                  # 查看服务状态
docker compose logs -f api         # 实时看后端日志
docker compose restart api         # 重启后端
docker compose up -d --build       # 更新代码后重新构建启动
docker compose down                # 停止（保留数据卷）

# 前端更新
cd vue-frontend && npm run build && systemctl reload nginx
```
