# AI应用开发实战课测试资料

## 1. RAG 的核心流程

RAG（Retrieval-Augmented Generation，检索增强生成）一般包含四个步骤：

1. 文档入库：把 PDF、Markdown、TXT 等资料解析成纯文本。
2. 文本切块：把长文档切成适合检索的小片段，并保留 source_id、source_name、chunk_index、course_id 等元数据。
3. 向量检索：把用户问题转成向量，在向量数据库中召回最相关的课程资料片段。
4. 生成回答：把召回证据和用户问题一起交给大模型，让大模型基于证据生成带引用的回答。

RAG 的业务价值是降低大模型幻觉，让回答基于企业或课程自己的资料，而不是只依赖模型通用知识。

## 2. chunk_overlap 的作用

chunk_overlap 是相邻文本块之间保留的重叠字符数。

如果 overlap 太小，句子可能被切断，导致检索片段缺少上下文。
如果 overlap 太大，会增加重复内容，导致向量库体积变大、检索成本变高。

在本项目中，chunk_overlap 用来在“语义完整性”和“检索效率”之间取得平衡。

## 3. MCP Server 和 MCP Client

MCP Server 负责暴露工具，例如本地知识库搜索、评估报告查询、运行日志诊断等。
MCP Client 负责发现工具、调用工具、传递参数并接收工具结果。

在 Agent 系统中，模型不是直接读本地文件，而是通过 MCP Client 调用 MCP Server 暴露出来的标准工具。

## 4. 课程级知识库隔离

真实业务系统中，不同课程的资料必须隔离。

例如：

- A 课程上传的资料，只能被 A 课程问答检索。
- B 课程上传的资料，只能被 B 课程问答检索。
- 学生不能跨课程读取其他课程资料。

所以每个文档 chunk 的 metadata 中都需要写入 course_id。
